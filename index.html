The missing piece: a JSON endpoint

Search API Decoupled

Turns an index into a configured, cacheable JSON endpoint. You pick the fields, facets, and page size in the admin UI.

Not a generic API

It is not JSON:API. It is one endpoint per search, shaped for that search. Access checks still apply.


GET /api/search/books?q=sea&f[0]=subject:Fiction

Contrib: drupal/search_api_decoupled

What is a web component?

A custom HTML tag the browser understands natively. No framework. No build step.


<search-root url="/api/search/books">
  <search-input></search-input>
  <facet-checkbox key="book_subject"></facet-checkbox>
  <search-results></search-results>
  <search-pager></search-pager>
</search-root>
  • Works in any theme, any page, any Drupal version that ships them.
  • Three browser APIs: custom elements, shadow DOM, templates.
  • It's just HTML. A site builder can place these.

Search Web Components

A contrib module

drupal/search_web_components — a library of ready-made search tags, plus blocks and a layout builder integration.

Built with Lit

Ships one bundled ES module. No npm needed on your site.

One shared context

<search-root> owns the query and the results. Everything inside it listens.

URL is the state

Back button works. Links are shareable. No extra work.

Your own layer, if you need it

Contrib is the engine. When a project keeps asking for the same extras, a small custom module on top can carry them. Anyone can build one.

Editor-friendly settings

Placeholder text, button labels, "no results" copy, facet labels — as config an editor changes in the UI.

Drupal blocks

Wrap the tags you use most as blocks, so site builders place search without touching Twig.

Enhancement JS

Autocomplete, load more, keeping facets when the keyword changes.

Twig-rendered results

Render each result through a view mode, so designers stay in Twig.

Why Lit?

Tiny

~5 KB. It is a helper on top of the browser, not a framework that replaces it.

Reactive properties

Change a property, the template re-renders. That's the whole API you need on day one.

Real HTML templates

Tagged template literals. No JSX, no compiler, no build step.

Standards, not lock-in

The output is a plain custom element. Anything can consume it.

A Lit component, whole


import { LitElement, html } from 'lit';

class ResultCount extends LitElement {
  static properties = { total: { type: Number } };

  render() {
    return html`<p>${this.total} results</p>`;
  }

  connectedCallback() {
    super.connectedCallback();
    document.addEventListener('swc-post-search', (e) => {
      this.total =
        e.detail.context.response?.search_results_count ?? 0;
    });
  }
}

customElements.define('result-count', ResultCount);

Now <result-count></result-count> works anywhere on the page.

You don't always need Lit


class MarginResultCount extends HTMLElement {
  connectedCallback() {
    document.addEventListener('swc-post-search', () => this.update());
  }

  update() {
    const response = document.querySelector('search-root')?.context?.response;
    const total = response?.search_results_count ?? 0;
    this.textContent = Drupal.formatPlural(total, '1 book', '@count books');
  }
}
customElements.define('margin-result-count', MarginResultCount);
  • Plain HTMLElement — no dependency at all.
  • Good when the component has no reactive state worth tracking.
  • From this demo's own code, lightly trimmed. Nothing to build.

Three ways to make it yours

1. Config

Sorts, page sizes, layouts, and which element renders a result. Set on the endpoint form and the blocks. No code.

2. Twig

Replace a component's markup with your own template, in your own theme. Same tag, your HTML.

3. A new component

Extend an existing tag, or define a brand new one. Listen to swc-post-search. Ship it in your own module.

Ladder of effort. Start at 1. Most requests never get past 2.

Bring your own result card


// Endpoint form, Result elements: books render as <margin-book-card>
class MarginBookCard extends HTMLElement {
  set data(value) {   // SWC hands over the raw JSON row
    this._data = value;
    this.render();
  }

  render() {
    const book = this._data;
    this.innerHTML = `
      <article class="book-card">
        <h3>${esc(first(book.title))}</h3>
        <p>${esc([].concat(book.author ?? []).join(', '))}</p>
      </article>`;
  }
}
customElements.define('margin-book-card', MarginBookCard);

SWC owns the results list. Your element owns each result. No patch, no fork.

Seams you can use

PHP

hook_preprocess_block() — change the props of a placed SWC block. Relabel a sort, set screen reader text.

JS

swc-post-search — fires after every search lands, Back button included. Bubbles and crosses shadow DOM. Analytics, counts, scroll restore.

Twig

A theme component with replaces: search_web_components:<tag> swaps the markup.

Subclass

Extend any tag's class. For example, override search-root's announcement text for a language with more plural forms.

The honest trade-offs

It needs JavaScript

No JS, no results. Fine for a search page. Not fine if search is your only navigation.

SEO

Don't expect search result pages to be indexed. They shouldn't be anyway — but know it going in.

Alpha upstream

search_web_components and search_api_decoupled are alpha. You need minimum-stability: alpha.

Accessibility is on you

Live regions, focus management, announcing result counts. The tags don't do it for free.

When to just use Views

  • A short list that rarely changes. Views.
  • No facets, no keyword box. Views.
  • Results must be crawlable. Views.
  • Site has no search server and won't get one. Views.

Reach for this stack when the page is interactive: many facets, live keyword search, big result sets, load-more.

Take these home

  • You can decouple one page without decoupling the site.
  • Web components are just HTML tags — site builders can place them.
  • Search API doesn't change. Only the rendering moves.
  • Lit is small. Twenty lines is a real component.
  • Subclass, don't patch. Custom elements make that easy.
  • Twig is still available when the design demands it.
